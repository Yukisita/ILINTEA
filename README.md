# ILINTEA（イリンテア）

**Integrated Live Information Terminal Application** の略称です。

配信・収録のスタッフと出演者で画面を共有する、ブラウザー型のプロンプターです。スタッフが編集した原稿・時計・画像・通知を、出演者の閲覧画面へリアルタイムに反映します。

1台のPCでサーバーを起動し、同じLAN内の複数端末から利用できます。編集・閲覧端末への専用アプリのインストールは不要です。
画面の同期にはWebSocketを使用し、同じブラウザーで複数タブを開いても編集用のHTTP接続を占有しません。

## 主な機能

- テキスト・時計・画像・TXT原稿・アラームの配置
- 複数端末でのリアルタイム編集・閲覧
- Previewで準備し、Programで閲覧者への表示を管理
- 原稿の自動スクロール、表示予約、アラームのカウントダウン
- 画面比率・背景色の変更、閲覧画面の反転・全画面表示
- 日本語・英語の表示切り替え

## 起動

.NET 10 SDKをインストールし、リポジトリのフォルダーで実行します。

```powershell
dotnet run --project ILINTEA.csproj
```

- 編集画面：<http://localhost:5280/>
- 閲覧画面：<http://localhost:5280/view/>

別端末で閲覧する場合は、編集画面の「閲覧URLをコピー」からURLを取得してください。ポートなどの設定は`ILINTEA.ini`で変更できます。

Visual Studioなどで通常ビルドした場合も、`bin/Debug/`または
`bin/Release/`の直下に実行ファイル・`ILINTEA.ini`・`wwwroot/`が揃います。
実行ファイルを直接起動する場合は、このフォルダーの内容を一式で配置してください。
設定と画面データは、起動時の作業フォルダーにかかわらず実行ファイルのフォルダーから読み込みます。
実行先には、.NET 10の次の共有ランタイムが必要です。

- .NET Runtime 10.x（`Microsoft.NETCore.App`）
- ASP.NET Core Runtime 10.x（`Microsoft.AspNetCore.App`）

[Microsoftの公式ダウンロードページ](https://dotnet.microsoft.com/download/dotnet/10.0)から導入できます。
Windowsの単体インストーラーでは、この2つを用意してください。.NET 10 SDKが導入済みなら、両方含まれています。

両構成をビルド後、`./tests/VerifyBuildOutput.ps1`で必要なファイルの配置とWebファイルの一致を確認できます。

## 画面の強調

編集画面上部の「画面を強調」で、すべての閲覧画面とProgramの枠を5秒間ゆっくり点滅させます。
閲覧側の全画面表示中にも届き、文字の追加や音はありません。
端末でアニメーションを減らす設定が有効な場合は、枠を点滅させずに表示します。
表示中に「強調を解除」を押すと終了します。強調は設定ファイルには保存しません。

## アラーム

「カウント中のメッセージ」「終了後のメッセージ」と終了日時を設定し、
「表示して開始」を押します。Programと閲覧画面にメッセージと残時間を表示し、
終了時刻にメッセージを切り替えます。終了後も残時間は`00:00:00`を表示します。
「終了日時を変更」で再設定でき、「非表示にする」または閲覧画面の
「通知を止める」で解除します。非表示のアラームは通知しません。音は鳴りません。

「指定時間後に表示」は全要素で利用できます。アラームも表示予約中は非表示・無効で、
表示時刻になると、設定した終了日時までの残時間を表示します。
表示前に終了日時を過ぎた場合は、表示時刻に終了後のメッセージと`00:00:00`を表示します。
予約の解除はアラームも解除し、「予約を解除して表示」は終了日時を維持して即時表示します。

設定ファイルには両方のメッセージを保存します。復元後のアラームは非表示・無効です。
設定ファイルはILINTEAの形式バージョン3に対応しています。旧形式の復元には対応しません。
TXT原稿は、編集後の本文をZIP内の独立したUTF-8の`.txt`ファイルとして保存し、
JSONには参照先を記録します。原稿は1件1GBまで対応し、空欄や改行も保持します。

## 利用上の注意

- 画面の内容はメモリー内だけに保持され、サーバーを停止・再起動すると失われます。
- 認証・権限管理は未実装です。信頼できるLAN内で利用し、インターネットへ直接公開しないでください。

## 画像の検証

PNG・JPEG・GIF・WebPを追加・差し替えするときは、ブラウザー標準の機能で画像の読み込みを確認します。
サーバー側ではSkiaSharp 4.153.1で全フレームの画素データを読み込み、ヘッダーだけの画像や破損した画像を拒否します。
読み込みや検査に失敗した場合はエラーを表示し、既存の画像を維持します。
設定復元にも同じ検査を適用します。デコードした画像のメモリー使用量も検査し、既存のファイル上限を超える画像は拒否します。

SkiaSharpとネイティブ部品は`ILINTEA.csproj`の`[4.153.1]`で版を完全一致に固定しています。
`packages.lock.json`とWindows x64発行用の`packages.win-x64.lock.json`には依存関係とパッケージのハッシュを記録し、通常の復元・ビルドはロックモードで実行します。
通常ビルドとWindows x64向けの発行では、記録した版が自動更新されることはありません。
依存関係がロックと食い違う場合は、別の版を採用せずエラーになります。

版を更新するときは、プロジェクトのバージョン指定を明示的に変更し、次の操作でロックも更新してください。
更新後は画像の検証と、配布する部品のライセンスを再確認します。

```powershell
dotnet restore ILINTEA.csproj -p:RestoreLockedMode=false --force-evaluate
dotnet restore ILINTEA.csproj --runtime win-x64 -p:SelfContained=false -p:RestoreLockedMode=false --force-evaluate
```
